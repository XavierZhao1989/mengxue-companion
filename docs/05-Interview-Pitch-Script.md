# 05 · 面试 6 分钟陈述稿与高频追问应答（JD 5 步通关版）

> 严格按照 JD 最后规定的 5 步顺序编排：**① 用户要完成什么 → ② 页面怎么走 → ③ 空和失败怎么处理 → ④ 界面为什么这样排 → ⑤ 最后代码怎么落地**。面试时建议**一边讲，一边点右侧控制台现场演示**。

---

## 一、6 分钟开场结构化陈述（可直接背诵/微调）

### 开场（20 秒）
“面试官你好，我带来的功能是儿童蒙学伴读产品**「启蒙小笺」**里最核心的**「每日 5 分钟亲子伴读与打卡闭环」**。这个项目是我从需求梳理、原型规范、移动端与管理后台编码到单测验证独立完成的。为了方便您检验细节，我还在桌面端右侧做了一个交互控制台，可以随时切换小屏、小程序形态、异常态和设计标注透视。”

### 第 1 步：用户要完成什么（45 秒）
“**目标用户是 3–8 岁孩子的家长**，典型场景是晚上睡前单手陪孩子读 5 分钟国学。我调研下来家长有三个真痛点：**一是不知道今天读哪篇，二是自己也不太会给孩子讲字词典故，三是很难坚持**。所以我把首页聚焦成一件事：家长打开 App，看到今天推荐的那一篇，单手点一下大按钮就能开始 5 分钟伴读；读到不会讲的生字，点一下就弹出白话解释和可以问孩子的互动问题，最后打卡拿正向反馈。如果家里连了智能伴读笔，右上角直接显示电量和同步状态。”

### 第 2 步：页面怎么走（50 秒）
“整个家长端收敛成 **3 个底部 Tab + 1 个沉浸式领读页**：
- 主链路是：**今日伴读首页 → 点击主按钮 → 逐句领读页 → 依次跟读或自动连读 → 最后一句完成打卡 → 盖章弹窗回到首页更新连续天数**；
- 分支链路有两条：**一是去「蒙学馆」按分类、年龄段或关键词选篇，一键设为今日伴读**；**二是从首页、蒙学馆或档案页都能进入领读页，我用 `returnTab` 记住了来源页面，点返回会精准回到来源 Tab**。同时如果在微信小程序环境下（*此时点右侧控制台切到「微信小程序」*），顶部右侧会自动留出原生胶囊避让区，保证按钮不被挡住。”

### 第 3 步：空和失败怎么处理（65 秒）
“小团队产品特别怕线上因为弱网或空数据出现白屏，所以我给每个页面都做了显式 5 态管理（*此时可点控制台「骨架屏加载」「空态引导」「接口报错」现场演示*）：
- **加载与弱网**：请求发出先出结构化骨架屏；如果超过 **800ms** 还没回来，顶部会出现温和的「网络有点慢，正在努力加载」提示；
- **空态**：比如新用户今天还没安排篇目，或者蒙学馆搜不到词，不会干巴巴写‘暂无数据’，而是给插画说明和一步直达的行动按钮（‘去蒙学馆挑一篇’或‘清空筛选条件’）；
- **失败与离线**：接口报错会展示清晰的原因、错误码和一键重试按钮；在领读完成点打卡时如果网络失败，页面不会丢掉孩子刚读完的成果，而是保留当前页允许内联重试打卡；离线模式下则回退本地缓存让家长能继续顺畅伴读。”

### 第 4 步：界面为什么这样排（65 秒）
“（*此时打开控制台「设计规范透视层」*）这套界面我是按**睡前护眼和单手拇指操作**来定规范的：
- **色彩**：不用刺眼的纯白和科技蓝，而是用宣纸暖白 `#FAF7F2` 做底、深墨 `#2C2621` 做字（对比度 >12:1）、朱砂暖橙 `#C85A32` 专管主按钮和重点字，夜间看着不累；
- **字号层级**：正文楷体用 `28px/46px` 给上方拼音留足呼吸空间；简介 `15px`、辅助标签 `12px`，主次一眼分开；
- **间距与触控热区**：全站遵守 8pt 间距系统（外边距 16px、主卡片 20px 内边距）；所有可点击图标保持 `≥44×44pt` 热区，首页主 CTA 做到 `52px` 高、领读播放键放在底部中心最顺手的位置。在 `iPhone SE 375×667` 小屏下我也专门测过，没有任何水平溢出和按钮挤压。”

### 第 5 步：最后代码怎么落地（60 秒）
“代码采用 **React 19 + TypeScript 严格模式 + Vite**，没有依赖笨重 UI 库，全部用语义化 CSS Tokens 落地（同时导出了一份符合 W3C 标准的 `design-tokens.json` 可直接对接 Figma/MasterGo）：
- 数据层抽了 `services/api.ts`，通过 `useAsyncData` Hook 统一接入 **`AbortController`**，防止家长快速搜索或切 Tab 时旧请求覆盖新结果；
- 语音领读封装了 `useSpeechReader`，优先调用浏览器中文语音合成，在静音或受限 WebView 下会自动平滑降级为节拍进度条，不卡死流程；
- 同时我也做了一个轻量的 **PC 运营管理后台**（*可切到「PC 管理后台」演示新增或上下架*），编辑或上下架篇目后切回手机端会立刻同步，并用 Vitest 补齐了状态流转、幂等打卡与竞态取消的单元测试。”

## 二、面试官高频追问应答锦囊

1. **Q：这些代码里有 AI 辅助吗？你如何对 AI 写的代码负责？**
   - 答：用 AI 加速样板代码和初始种子内容生成，但**状态机边界、CSS Token 规范、`AbortController` 竞态防线、小屏安全区适配以及核心逻辑单元测试**都经过我自己逐行审查与浏览器真机模拟验收，任何一行代码的设计取舍我都能讲清。
2. **Q：如果真要做成微信小程序或 App，这个 H5 架构怎么迁移？**
   - 答：领域类型 `types/domain.ts`、日期/业务纯函数和 `services/api.ts` 抽象层与视图完全解耦，迁移到 Taro/UniApp/React Native 时只需把 UI 容器替换成对应端组件（如 `View/Text`、`wx.createInnerAudioContext`），状态逻辑几乎零重写。
3. **Q：你们上线后最容易踩的坑是什么？你怎么防的？**
   - 答：可从 `docs/04-Architecture-and-Postmortem.md` 里的 3 个真实案例任选 1–2 个展开（推荐讲 **「`100dvh` + 安全区底栏遮挡」** 和 **「弱网连点/竞态与幂等打卡」**），结构严格按：**线上现象 → 根因定位 → 修复方案 → 工程防线**。
